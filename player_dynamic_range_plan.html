Dynamic Time-Range Player Stats

Implementation plan — keep the 4 preset windows, add arbitrary same-season date ranges, all backed by our stored daily box scores.

frontend flag · VITE_FF_CUSTOM_RANGE

Today the 4 windows come from ESPN precomputed splits. This moves all stat windows onto our fs_player_games table (Layer 1), keeps ESPN as a per-player fallback for the 4 presets only (Layer 2), and adds a custom date-range picker to the shared selector — which lights up Players, PlayerRankings, TeamDetail and Trade at once.

BackfillNot needed — offseason; fresh data inherits the new filter.

Per-player resolution flow

2 · Matched + 0 games → all 0.0 row, gp 0

4 · Backend plan (Layer 1 + Layer 2)

models/player.py
Add CUSTOM = "custom" to StatTimePeriod. Add helper resolve_window(period, start, end, season_start) → (start_date, end_date). Keep to_stat_split_id (fallback key; custom → 0 for metadata only).
routes/players.py
Add optional start/end query params. Validate exactly like routes/analytics.py: both-or-neither, start<end, start≥season_start, end≤today, custom requires both → 422.
services/player_service.py
Resolve window → call new aggregation → join ESPN metadata by normalized name → apply fallback rules → build PaginatedPlayers (shape unchanged). Add actual_start/actual_end to response for the coverage note.
services/team_service.py
Twin path — same resolve→aggregate→fallback for TeamDetail's time_period.
services/db_service.py
New aggregate_player_games(start, end, season) → DataFrame: GROUP BY player_id, SUM counting stats, SUM(makes)/SUM(attempts) for FG%/FT%, COUNT(*) gp, filter min > 0. Aggregate in SQL — return ~500 rows, not raw.
migrations/…sql
New composite index (season, game_date) on fs_player_games. Manual apply (your convention).
override dict
Small ESPN→NBA name override map + a miss-log line so the tail is patchable without blocking launch.

5 · Storage / model change (unconditional — ships before next season)

serving/nightly.py
Two write filters MIN ≥ MIN_MINUTES → MIN > 0: fetch_night() (daily append) & bootstrap_frames() (seed). Table now stores every game actually played.
db_service.get_fs_rows_before
Add WHERE min >= 2 at this single model-read boundary → model vectors/training behave exactly as today.
season simulator
Verify the ingest_prederived slice source (feature_store.py:150) applies the same ≥2 filter, since its frames now carry >0 rows.
ℹ
Why safe: serving gates on MIN_INFERENCE_GAMES (a game count), not per-game minutes. The ≥2 filter is the model's concern, moved to read-time. Storage becomes raw truth → our gp matches ESPN's gp.
