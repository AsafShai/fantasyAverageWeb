Box Scores Page — Plan

A new /box-scores page that shows the box scores of the latest NBA games (default: the most recent night with finished games), with a Spoiler Shield that hides results until the user chooses to see them.

1. Mockup (clickable)

Use the Spoiler Shield switch, the per-game Reveal links, and the cards. All data below is made up.

The game strip is on top, and the selected game's box score is below it. On desktop the two team tables could sit side by side; the mockup uses tabs, which work at every width.

2. What the page shows

  • Date navigator: prev/next night plus a date picker. By default it opens on the latest night that has a final game. If a night is in progress, it opens on that night and the live games show their status.
  • Game strip: one card per game with teams, score, and status (time, live clock/period, or Final). A dot marks games that include a player from my fantasy team (from MyTeamContext).
  • Box score panel for the selected game:
    • Line score (Q1–Q4 + OT + total).
    • Per-team player table: starters, then bench, in ESPN's order. Columns: MIN, PTS, REB, AST, STL, BLK, TOV, FG, 3PT, FT, OREB, PF, +/-. Team totals row and team FG/3P/FT %.
    • DNP list with the reason ESPN gives (e.g. "DNP – Coach's Decision", "Out – Ankle").
    • Rows for my fantasy team's players are highlighted. Names link to /player/:id through PlayerNameLink.
  • Deep link: /box-scores?date=2026-10-24&game=401810123, so a game can be shared and the back button works.

3. Spoiler Shield

This is the main design question. Hiding only the final score isn't enough, because many other things on the page also give the result away:

Leaks the resultWhat the shield does
Final score, W/L styling (grey loser)Show •• masks with a fixed width, so a 2-digit vs 3-digit score can't be guessed from layout. No winner styling.
"Final/OT" statusShow "Final" only. An overtime label tells you the game was close.
Live score / period / clockShow "In progress" only.
Line scoreHidden.
Player stats, minutes and +/-The whole table is hidden behind the gate. Minutes alone give away a blowout (starters sitting out the 4th).
Row order (sorted by PTS)Rows always use ESPN's starters → bench order, even when revealed. That keeps the layout the same in both modes.
Browser tab title, share imagesThe title stays "Box Scores", never "LAL 112 – BOS 108".
Not rendered, not blurred. When shielded, the numbers are left out of the DOM. A CSS blur still exposes them to text selection, find-in-page, screen readers, browser translation, and a flash before the styles load.
Three levels: (1) the page-wide switch, saved with usePersistedState('boxScores.spoilerShield', …); (2) a per-game Reveal, remembered for the session in sessionStorage by event id, so revealing the Lakers game doesn't reveal the others; (3) "Hide again" on a revealed game.
Hiding happens on the client. The API always returns full data. The shield is a UI concern, so RTK Query caching stays simple and switching the shield never refetches.
Open question — default state. I recommend off by default, with the user's choice saved. Most visitors come to check stats, and anyone who cares about spoilers turns it on once. The other option is on by default, which is safer (you can't un-see a score) but costs everyone else a click on every visit.
Open question — fantasy angle (v2). "Reveal my players only": show my fantasy players' lines with +/- and team totals hidden. Their own numbers still hint at the result, so it is only a partial shield. It should ship as an explicit opt-in, not as part of v1.
Other pages (Today, Trends, player game logs) also show recent results. The shield applies to this page only. Making it site-wide would be a separate, much bigger change.

4. Data source

We already store box scores in fs_player_games / fs_team_games, but that data was built for the model and doesn't fit this page well:

Needfs_* tablesESPN summary (live)
Player lines, team score✅✅
Line score by quarter, OT❌✅ header.competitions[0].competitors[].linescores
Starters / bench, DNP reasons❌ (DNPs dropped)✅
Tonight's games, live❌ (morning ingest, finals only)✅
Preseason / playoffs / NBA Cup final❌ (filtered out)✅
Fetch from ESPN live and cache, without touching the fs tables. The new service reuses the existing ESPN client (model_stats_inference/espn/client.py: scoreboard + summary?event=). It writes no new tables and doesn't change the model pipeline. Caching: final games never change, so they're cached for 24h. Live games are cached for 30–60s, and scoreboards for 60s. A night is ~15 requests, so a cold cache after a restart is cheap.

If we later want history without ESPN (or something more durable than an in-memory cache), add a box_score_cache(event_id PK, payload JSONB, final BOOL, fetched_at) table. That isn't needed for v1.

5. API

GET /api/box-scores?date=YYYY-MM-DD

If date is left out, the server picks the latest night with a final game (from the scoreboard calendar it already uses). The response is a list of games:

{ "date": "2026-10-24", "prev_date": "2026-10-23", "next_date": null,
  "games": [{ "event_id": "401810123", "status": "final", "period": 4, "overtime": false,
              "start_time": "...", "clock": null, "season_type": 2,
              "home": { "team_id": 13, "abbr": "LAL", "name": "Lakers", "score": 112 },
              "away": { ... } }] }

GET /api/box-scores/{event_id}

{ "event_id": "...", "status": "final", "overtime": false,
  "teams": [{ "team_id": 13, "abbr": "LAL", "linescore": [28, 30, 25, 29], "score": 112,
              "totals": { "fgm": 42, "fga": 88, ... },
              "players": [{ "player_id": 1966, "name": "...", "position": "F", "starter": true,
                            "min": 36, "pts": 28, ..., "plus_minus": 9 }],
              "dnp": [{ "player_id": ..., "name": "...", "reason": "Out – Ankle" }] }] }

My-team highlight: the frontend already has the fantasy roster. ESPN fantasy player ids are ESPN athlete ids (the same ids fs_player_games uses), so matching on id is enough; no name join is needed. Phase 1 should check this against a real roster, since a few services still match by name.

6. Files

Backend

  • app/services/box_score_service.py: async fetch with the shared httpx client and the TTL cache, plus parsing. It reuses the stat-name and made-attempted helpers from espn/games.py where they fit, and adds linescore/starter/DNP parsing.
  • app/models/box_score_models.py: Pydantic response models.
  • app/routes/box_scores.py: registered in main.py under /api/box-scores.
  • tests/services/test_box_score_service.py: parsing against saved ESPN JSON fixtures (final, OT, live, a DNP with no athlete id, an All-Star-style event). Route test in tests/routes/. Extend tests/live/test_espn_contract.py to check the linescore/starter fields.

Frontend

  • src/pages/BoxScores.tsx: route /box-scores behind a new FF_BOX_SCORES flag, plus a nav entry in Layout.tsx and the command palette.
  • src/components/boxScores/: GameStrip, GameCard, LineScore, TeamBoxTable (TanStack Table, like the other tables), SpoilerShieldToggle, SpoilerGate.
  • src/hooks/useSpoilerShield.ts: the global flag plus the per-game revealed set, with an isHidden(eventId) function. Components only call this, so none of them handle shield logic themselves.
  • src/store/api/fantasyApi.ts: getBoxScoreDay / getBoxScore endpoints. Use pollingInterval: 60_000 only while a game on the shown night is live.
  • Tests: the shield hides every leak in the table above (score, OT, minutes, +/-, line score, title); the per-game reveal leaves other games hidden; the persisted switch survives a reload.

7. Phases

  1. Backend: service, endpoints, fixtures, and tests.
  2. Page without the shield: date nav, strip, box score panel, my-team highlight, deep links.
  3. Spoiler Shield: the global switch, per-game reveal, and the leak tests.
  4. Extras: links in from a player's game log (Player Profile/Trends) to that game's box score, and "Reveal my players only".
