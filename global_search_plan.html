Desktop vs mobile

Desktop

  • Ctrl/⌘+K global listener; ignored while typing in another input.
  • Visible navbar control so it's discoverable without knowing the shortcut.
  • Centred overlay, ~520px, max 300px list. Arrows + Enter, Esc closes, click-outside closes.
  • Focus returns to whatever was focused before opening.

Mobile (≈390px)

  • No keyboard shortcut — a 🔍 icon sits left of the ☰ hamburger.
  • Overlay goes full-screen: input pinned top, results fill the rest, keyboard-safe.
  • Rows are 44px tall, footer hint row hidden.
  • This is the bigger win. Today there is no global player search on mobile at all — the only search input lives inside the Trade page.

Cost

  • No new dependency. Fuzzy match is token/prefix filtering over arrays already in cache — no cmdk, no fuse.js.
  • Reuse: components/PlayerSearchInput.tsx already has the debounce + dropdown + click-outside pattern; lift its logic instead of rewriting.
  • New: components/CommandPalette.tsx, hooks/useGlobalSearch.ts (merges + ranks the four sources), constants/searchablePages.ts.
  • Edit: Layout.tsx and ReorgLayout — mount the palette, add the desktop control and the mobile icon.
  • Backend: none.

Open question for you: if the player list isn't already in cache on every page, the palette either fetches it on first open (small delay once) or prefetches it at app boot. Prefetch is one extra query on load — cheap, but it's your call given Render cold starts.
